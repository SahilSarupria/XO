# Acceptance criteria (proposed, unmeasured)

Every number below is a **proposal**, chosen so a later evaluation round has something to pass or fail. **None of them has been measured.** The only measured results
in this repository are in `docs/ROADMAP.md` section A (freight claims, one model) and the second-domain offline measurement already recorded there. Each row names the
evaluation that would verify it, so the eval round is a checklist rather than a design exercise. No live evals, second-provider runs, or cost/hardware benchmarks were run for this document.

Status of every row: **proposed, unmeasured**.

| #   | Criterion                                                                        | Proposed target                                                                                                                      | Verified by (deferred eval)                                                                                                                           |
| --- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Minimum task accuracy, decision workflows, per domain                            | >= 90% agreement with the independent oracle on fresh seeds, with the 95% lower bound >= 85%                                         | Per-domain `xo ab-eval` on seeds not used for tuning, tree-tool arm                                                                                   |
| 2   | Unsafe-action rate (auto-approving or acting when the oracle says escalate/deny) | 0 in every run; any single occurrence fails the gate                                                                                 | Abstention and adversarial task sets, all arms; plus `xo flow compare` on shadow runs                                                                 |
| 3   | Escalation correctness                                                           | >= 95% of oracle-escalate cases escalate; <= 20% of oracle-decidable cases are escalated needlessly                                  | Abstention task set; shadow-mode comparison against human decisions                                                                                   |
| 4   | Latency, deterministic path (structured input, no model, local)                  | p95 <= 50 ms per run excluding connector time                                                                                        | Hardware benchmark (deferred), `xo flow run` over 1,000 structured cases                                                                              |
| 5   | Latency, one model-assisted extraction                                           | p95 <= 8 s with a hosted model, <= 20 s with a small local model                                                                     | Per-provider eval with fixed prompts                                                                                                                  |
| 6   | Maximum cost per successful task, free-text path                                 | <= 1 model call per case; <= 20% of the plain-model arm's cost per correct answer                                                    | Cost comparison (existing `cost-compare` tooling), deferred                                                                                           |
| 7   | Model calls on structured input                                                  | exactly 0                                                                                                                            | Already asserted by unit tests; confirm on real traffic with `xo flow explain` model-call totals                                                      |
| 8   | Memoization effectiveness                                                        | >= 90% of repeated identical cases served without a model call                                                                       | Replay of a repeated-case traffic sample                                                                                                              |
| 9   | CPU / RAM, local operation                                                       | deterministic runner <= 256 MB RSS and <= 1 core sustained for 50 runs/s; low-resource mode <= 128 MB                                | Hardware benchmark (deferred) on a reference small host                                                                                               |
| 10  | Crash recovery                                                                   | 0 lost or duplicated external effects at systems that honour idempotency keys across 1,000 injected crashes                          | Fault-injection at every journal boundary (`duplicate-window.test.ts`) over keyed, lookup-capable and unattested fakes; a 1,000-crash soak is not run |
| 11  | Failover                                                                         | takeover within 2 x lease TTL of the last heartbeat; 0 double executions at idempotent systems                                       | Two-runner soak with injected freezes (see `docs/FAILOVER.md`)                                                                                        |
| 12  | Cross-provider consistency                                                       | <= 3 percentage points difference in task accuracy between any two supported providers; identical decisions on every structured case | Second-provider eval (Gemini, OpenAI, Azure, Ollama); structured cases need no provider                                                               |
| 13  | Cross-domain generalisation                                                      | >= 85% agreement with the oracle in a third domain compiled with no hand-edited trees, and <= 10 points below the best domain        | Third-domain offline compile-and-measure                                                                                                              |
| 14  | Compiler coverage                                                                | >= 80% retrieval recall and >= 90% of gold-XO facts present, on fresh seeds                                                          | `scorePackage` / `compilerGap` (offline, no model)                                                                                                    |
| 15  | Determinism ratio                                                                | reported per workflow with its reasons; no target is set because it depends on the organization's documents                          | `xo flow report` (declared) plus shadow runs (observed)                                                                                               |
| 16  | Audit integrity                                                                  | 100% of exported bundles verify; 100% of single-byte edits detected                                                                  | Property test over random bundles (cheap, can run now)                                                                                                |
| 17  | API hardening                                                                    | all adversarial cases in `packages/sdk/test/api.test.ts` pass; no new 5xx on a fuzzed route set                                      | Fuzz run (deferred)                                                                                                                                   |

Notes

- Rows 7, 10 (partly), 16 and 17 have unit or integration tests today; those tests show the mechanism works on small fixtures, not that the targets hold at scale.
- Targets are deliberately conservative defaults, not claims. Replace them with numbers the business actually needs before using them as a release gate.
- A row is "met" only when the named eval has been run and its output is linked from `docs/ROADMAP.md`.
