# Draft workflow execution: discovery note

Status: design decision for Studio Phase 1, task 3. Read from the code at 9ac8ca4; nothing here is implemented yet.

## How things work today

- **Derived workflows** (`apps/api/src/workflows/*`) run a `CandidateWorkflow` that `@xo/workflow-composer` derives from one stored compilation. `driveWorkflow` re-derives the workflow from that compilation on every start and resume, and fails closed (`WORKFLOW_NOT_EXECUTABLE`) if the persisted steps no longer equal the composed ones. Steps run strictly in order. The gate per step is `authorizeStep` (capability approved in this workspace, then contract permissions under the empty fail-closed policy), then input-schema validation, then the unmodified `RuntimeCapabilityExecutor`.
- **Human tasks** exist only as an execution record whose binding is `human_in_the_loop`: the executor returns `escalation_required`, the step becomes `waiting_for_human`, and the execution id IS the task id. Resolution goes through `resolveHumanTaskExecution` and workflow resume.
- **Draft definitions** (`workflow-definitions/*`) are stored and analysed only. `analyzeDefinition` always returns `runnable: false`; `POST .../run` always answers 501.
- **Confidence**: executions return no confidence value. The only confidence is the compile-time `contract.confidence` of a capability (static per rule, visible in preview).

## Mapping decision

| Draft node                                        | Decision                                                                        | Engine mapping                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `trigger` type `manual`                           | supported                                                                       | Run input is the trigger payload (same as workflow `input`).                                                                                                                                                                                                                                    |
| `capability`                                      | supported                                                                       | One execution record per visit via the existing execution store, behind `authorizeStep` and schema validation. Needs an additive optional config field `compilationId`; without it the node is a blocker. `packageName` stays a display label; nothing on the server resolves packages by name. |
| `human_review`                                    | supported only directly after a capability whose binding is `human_in_the_loop` | The capability's own escalation opens the task. A standalone review step has no engine primitive and is a blocker.                                                                                                                                                                              |
| `branch` (`confidence`, `gte`/`lt`)               | supported                                                                       | Compares the upstream capability's declared contract confidence (static, read from the stored compilation) with the threshold. The note and run record say so; it is not a measured result.                                                                                                     |
| `trigger` `schedule`, `document_dropped`          | rejected                                                                        | No scheduler or drop watcher exists.                                                                                                                                                                                                                                                            |
| `action` (`webhook`, `email`)                     | rejected                                                                        | No delivery exists.                                                                                                                                                                                                                                                                             |
| `capability` with `memoryScope` other than `none` | rejected                                                                        | Memory scopes are not part of the runtime.                                                                                                                                                                                                                                                      |
| `compile`, `validate`                             | rejected                                                                        | No step runs the compiler or validator from a workflow.                                                                                                                                                                                                                                         |
| fan-out, joins, loops, several triggers           | rejected                                                                        | The driver is sequential; a branch takes exactly one path.                                                                                                                                                                                                                                      |

## Runnable means

Well-formed, one manual trigger, a single path of supported nodes, every capability node names a compilation that succeeded, and every capability resolves to a deterministic or HITL binding. The run still refuses at start if a capability is unapproved or a permission is missing.

## Implementation shape (task 3)

- New driver `workflows/draft-runner.ts` reusing `authorizeStep`, the execution store and `RuntimeCapabilityExecutor`. `driveWorkflow` is not reused because its mismatch check is tied to composed workflows.
- Run record is a `WorkflowExecutionRecord` with `workflowId = draft:<definitionId>`, plus the draft revision it ran, so it appears in the existing runs and inbox views and resumes through the existing human-task path.
- `analyzeDefinition` gets the compilation lookup as input, so `runnable` is true only when the checks above pass. `runnable` widens from `false` to `boolean` in the contract (additive for readers that treat it as boolean).
- Branch evaluation, node visits and audit events (`workflow.draft_run_started`, per-step, resolved) are written to the run record and audit log.
